# generic-harunobu

Googleスプレッドシート上で動作する **GAS（Google Apps Script）製の機械可読性チェッカー MVP** です。
デジタル庁が公開する「行政データにおける機械可読性に関するルール」を参考にした**独自実装**であり、公式の「Harunobu」の移植版・公式製品ではありません。

- 公式案内: https://www.digital.go.jp/resources/machine-readability-rule/harunobu
- 公式ルール（JSON）: https://github.com/digital-go-jp/machine_readability_rule/blob/main/machine-readability-rules.json

## 使い方（最短）

1. チェックしたいGoogleスプレッドシートを開く。
2. **拡張機能 → Apps Script** を開く。
3. `Code.gs` の全文をスクリプトエディタの `コード.gs` に貼り付けて保存する。
4. スプレッドシートを再読み込みすると「**機械可読性チェック**」メニューが現れる。
5. **現在のシートを検査** または **全シートを検査** をクリックし、初回はGoogleの権限確認を承認する。
6. `機械可読性_検査結果` シートに **ルールID／問題セル／理由／修正案** などを出力する。`対象セルへ` のリンクから問題箇所を開ける。

> 「全シートを検査」でも `機械可読性_検査結果` は除外します。検査結果シートは再実行で上書きされます。元データの値・書式は変更しません。

`appsscript.json` はV8・Asia/Tokyo・現在のスプレッドシートのみへの権限を想定した構成です。必要ならエディタのプロジェクト設定でマニフェストを表示し、こちらの内容をコピーしてください（**既存のマニフェストは安易に上書きしないでください**）。

## MVPで検査するルール

| ルールID | 検査内容 | 判定の限界 |
| --- | --- | --- |
| L1-03 | データを分断する完全空白行・列 | 意図的な区切りを誤検出することがあります |
| L1-05 | 1行目の列見出しの欠落 | 1行目がヘッダーという前提です |
| L1-06 | 文字列先頭・末尾の不要そうな空白 | 意図的な空白も候補として表示します |
| L1-07 | セル内改行（複数データの疑い） | 改行だけで違反とは断定しません |
| L1-12 | データ範囲内の結合セル | 構造上の指摘です |
| L2-01 | 桁区切り・単位付きの数値文字列 | 識別子や自由記述は修正対象とは限りません |
| L2-03 | 重複する列見出し | 1行目のみをチェックします |
| L2-05 | `その他（内容）` 形式のカテゴリと自由記述の混在 | パターン一致のみです |
| L2-06 | 数式の残存 | 業務用の計算シートでは正しい設計の場合があります |
| L3-01 | 先頭の空白・タイトル行らしき構造 | 推測判定です |

ルールIDは公式ルールのものを使っていますが、**判定アルゴリズム・適用範囲・重要度はこのMVP独自**です。公式Harunobuのスコア・合否・適用条件を再現しません。チェックしていないルールは「合格」扱いではありません。

## 設計上の前提と制限

- 原則として **1行目が見出し、2行目以降がレコード** の表を想定します。入力フォーム・集計表・ダッシュボードでは多くの指摘が意図的な設計に該当する可能性があります。
- `要修正` は比較的客観的な構造上の指摘、`要確認` は人が文脈を見て判断する候補です。
- 1シート当たり最大 `100000` セルを読み込みます。超過シートは検査せず `SYSTEM-SKIP` として表示します。
- 全シートの結果は最大 `4000` 件です。超過時は `SYSTEM-LIMIT` で**結果が不完全**なことを明示します。
- **表の自動推定、コード表の照合、表記揺れの高度な分析、非表示行・列の調査、画像・図形の検出、本家の100点採点** は未実装です。
- **外部APIへのデータ送信はしません**。処理はGoogle Apps ScriptとGoogleスプレッドシート内で完結します。ただしクラウドサービス上で実行されるため、ローカル実行の公式Harunobuと実行環境は異なります。
- `検査結果` シートの内容は同じスプレッドシートへのアクセス権を持つ他の閲覧者にも見える場合があります。
- セル位置は実際のA1表記で出力され、セルへのリンクを生成します。空白の行・列は `2:2` / `B:B` のように表記します。

## 開発・テスト

GASエディタ上の実行とは別に、判定ロジックのみをNode.js組み込みのテストランナーでテストします。

```bash
npm test
```

`inspectGrid_` はGoogleサービスに依存しないため、ローカルでテスト可能です。`onOpen` / 出力シートへの書込み等はGAS実環境で別途結合テストしてください。

## 利用にあたって

本リポジトリのソースは独立して書き起こしたもので、公式HarunobuのPythonコードや公式JSONルール定義を同梱していません。公式プロジェクトの名称や出典への言及は参照目的です。
