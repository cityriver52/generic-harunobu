# generic-harunobu

GoogleスプレッドシートのURLを入力し、**複数のスプレッドシートを1つの画面から診断できるGAS Webアプリ**です。

デジタル庁の[公式Harunobu](https://www.digital.go.jp/resources/machine-readability-rule/harunobu)を出発点に、その[公開機械可読性ルール](https://github.com/digital-go-jp/machine_readability_rule)を**Google Workspace内で完結するように再設計・GASで独自実装した非公式の派生ツール**です。公式Pythonコードを直接改変・移植したものではなく、公式スコア・判定を再現するものではありません。

**AI機能なしで公式30項目のうち23項目を直接検出または参考判定します。** ただし網羅的な適合判定ではありません。[30項目の対応表と制限 → RULE_COVERAGE.md](RULE_COVERAGE.md)

## 機能

- URLを貼り付けて診断。対象ファイルの全ワークシートを走査（生成した結果シートを除外）。
- 重要度、ルールID、対象シート、問題セル、理由、修正案をWeb画面に表示。重要度フィルターとキーワード検索も可能。
- 問題セルへのリンクから元のシートを開ける。
- 対象ファイルに編集権限があれば、同じファイル内の **`機械可読性_検査結果`** に全検査結果を出力する（実行ごとに上書き）。
- 閲覧権限しかないファイルでも、検査自体が成功すれば **Web画面上で先頭250件の指摘** を確認できる。結果シートには保存されない。
- **元のデータシートの内容・書式は変更しない。** ただし、対象ファイルへの結果シートの新規作成・上書きは行う。
- 旧来のスプレッドシート組み込みメニューも `Code.gs` に残している（Webアプリ利用時は不要）。

## Webアプリの導入手順（初回のみ）

1. [Google Apps Script](https://script.google.com/home/projects/create) で **新しい独立したプロジェクト** を作成する。診断する各スプレッドシートにスクリプトを入れる必要はありません。
2. エディタの `コード.gs` をリポジトリの **`Code.gs`** の内容で置き換える。
3. エディタ左の「ファイル」横の **＋ → スクリプト** からファイル名を **`ExtendedChecks`** として作成し、**`ExtendedChecks.gs`** の内容を貼り付ける。**このファイルは必須です（拡張23ルールの検査エンジン）。**
4. **＋ → HTML** でファイル名を **`Index`** として作成し、リポジトリの **`Index.html`** を貼り付ける。
5. 左の「プロジェクトの設定」→ **「appsscript.json マニフェスト ファイルをエディタで表示する」** を有効にして、表示されたマニフェストを **`appsscript.json`** の内容で置き換える。*新規プロジェクト用の設定です。別アプリの既存設定を上書きしないでください。*
6. 保存して **「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」** を選ぶ。
7. 推奨設定は **「次のユーザーとして実行：ウェブアプリケーションにアクセスしているユーザー」**。アクセスできるユーザーは、初回は **「自分のみ」** を推奨。組織内で共有する場合も、利用範囲を組織に制限する。
8. デプロイして、発行された `/exec` のURLを開く。案内に従ってGoogleアカウントで承認し、診断したいスプレッドシートのURLを貼り付け、「診断を実行」を押す。

詳しいデプロイ仕様: [Google公式 — Web Apps](https://developers.google.com/apps-script/guides/web)。開発中は「デプロイ」→「デプロイをテスト」の `/dev` URLでも確認できます（エディタ権限がある人に限定）。

### なぜ従来より広いGoogle権限が必要？

Googleの `SpreadsheetApp.openById` により任意のスプレッドシートを開くため、`spreadsheets.currentonly` ではなく **`https://www.googleapis.com/auth/spreadsheets`** のOAuthスコープが必要です。これは広い権限です。コードとデプロイ対象を確認した上で承認してください。

**重要:** Webアプリを **「自分として実行」** かつ **「全員に公開」** とすると、訪問者の指定したURLに対して*デプロイ者の権限*で読み書きする可能性があり、危険です。**不特定多数に公開しないでください。** 他者にも使ってもらう場合は **「アクセスしているユーザーとして実行」** にし、各ユーザーがアクセス可能なファイルだけを扱う設計にしてください。Google Workspaceの管理者ポリシーによっては認可・公開が制限されます。

## 利用フロー

1. Webアプリを開く。
2. `https://docs.google.com/spreadsheets/d/.../edit` を貼り付ける。共有リンクのクエリや `#gid=` が付いていても使用可能。
3. 診断完了後に **サマリー / 指摘一覧 / セルリンク / 結果シートリンク** が表示される。
4. 別のURLを貼り付けて繰り返し診断可能。過去の診断結果をWebアプリ側には保存しない。

**閲覧権限だけのファイル:** 診断はできるが、対象ファイルに結果シートを作成できないため、Web画面のみで確認します。Web画面表示は先頭250件までです。診断件数がそれより多いとき、全件保存がない場合は全件を確認できません。

**既存の同名シート:** `機械可読性_検査結果` が存在して、過去の本ツールによる結果シートでない場合は、**ユーザーのデータを保護するため上書きせず**、Web画面の結果のみ返します。

## 検査ルール（独自実装）

旧MVPの10項目に加えて13項目の判定を追加しました。以下は旧MVPの10項目の概要です。拡張した13項目の内容と、未対応・手動確認の7項目は[全30項目対応表](RULE_COVERAGE.md)に記載しています。

| ルールID | このMVPの検査内容 | 留意点 |
| --- | --- | --- |
| L1-03 | 表を分断する完全空白行・列 | 意図的な空行・列も候補になる |
| L1-05 | 列見出しの欠落 | 1行目が見出しという前提 |
| L1-06 | 先頭・末尾の空白 | 意図的な空白も検出する |
| L1-07 | セル内の改行 | 複数データの疑いを表示 |
| L1-12 | 結合セル | 構造上の指摘 |
| L2-01 | 単位付き・桁区切りの文字列数値 | 識別子なら修正不要 |
| L2-03 | 重複する列見出し | 1行目のみ |
| L2-05 | `その他（詳細）` の混在 | パターン一致のみ |
| L2-06 | 数式の残存 | 業務用の数式は必要なこともある |
| L3-01 | 表題行や先頭空白行らしい構造 | 推測判定 |

- ルールIDは参考元に対応させていますが、**判定ロジック・重要度・適用範囲は独自**です。検査で指摘0件でも、本家のルールに全合格したことにはなりません。
- 1シートの使用範囲が **100,000セル超** の場合はスキップします（結果に通知）。指摘は最大 **4,000件** までです。超過は画面・結果シートで明示します。
- Web画面の表示は **先頭250件** です。全件は出力された結果シートで確認してください。
- 表の自動認識、表記揺れの高度な判定、画像や図形、公式採点は未実装です。
- タイトル行や数式を多用する業務用シートは誤検出が起きやすいため、**公開・外部連携する表形式データ** を主な対象としてください。

## セキュリティ・プライバシー

- URLは `https://docs.google.com/spreadsheets/d/` 形式に限定し、任意URLへの通信はしません。
- データはGoogle Apps Script経由でスプレッドシートから読み取ります。**外部APIや独自サーバーへ送信しません。** ただしGASとSheetsはGoogleのクラウドサービスです。
- 結果シートを保存した場合、対象ファイルの閲覧者にも指摘内容が見えることがあります。
- セル内の文章の一部が「理由」に入ることがあり、診断結果自体にも情報が含まれます。機密資料の診断は共有権限を確認してください。
- デプロイ権限やGoogle認証が不適切な場合はファイルを開けません。OAuthの承認は各ユーザーが行います（「アクセスしているユーザーとして実行」の場合）。

## 開発とテスト

```bash
npm test
```

Node.js組み込みテストで検査ロジック・URL検証・Web経由の読み取りなどをテストします。**実際のGAS実行やWebアプリデプロイの結合テストは別途必要**です。

主なファイル:

- `Code.gs` : 診断エンジン + Webアプリのバックエンド
- `ExtendedChecks.gs` : AIなしで判定する13項目の追加ルール、Sheetsの非表示行・オブジェクト情報収集
- `RULE_COVERAGE.md` : 公式30項目とGAS判定の対応表、限界
- `Index.html` : ブラウザUI
- `appsscript.json` : 全スプレッドシート向けのOAuthスコープ
- `tests/*.test.cjs` : Node.jsテスト
